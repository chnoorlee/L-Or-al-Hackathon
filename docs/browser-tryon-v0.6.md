# 手机浏览器虚拟试妆 v0.6

2026-10-18。按用户选择新增 H5 入口，保留现有小程序。参考 [L’Oréal Paris 虚拟试妆](https://www.lorealparisusa.com/virtual-try-on-makeup) 的品类、商品、色号、叠妆、比较、收藏与保存流程，使用自己的界面和公开模型实现。

## 使用与实现

`npm run web:assets` 准备本地运行库及校验过的模型；`npm run web:build` 生成 `dist/web`；`npm run web:serve` 仅将这个目录通过 `127.0.0.1:4173` 提供给本机。手机需 HTTPS 站点，不能直接使用普通局域网 HTTP。开发入口为 `npm run web:dev`。

打开实时镜头或上传照片，选品类、商品和色号，分别设置浓度与模拟质感。图层可以叠加或独立移除，也可全部清除。原图按住对照、可调分屏、前后镜头切换、镜像切换、PNG 保存、收藏色号、保存并恢复妆容均已实现。商品详情链接指向对应的官网页面，不构建支付流程。

| 区域 | 实现 |
| --- | --- |
| 粉底 | 面部轮廓内上色，排除眼睛、眉毛、嘴唇、鼻部 |
| 遮瑕、修容、腮红、高光 | 眼下、外侧面颊、双颊及颧骨的独立蒙版 |
| 唇膏、唇彩 | 外唇轮廓减去口腔开口，保留明暗纹理 |
| 眼影、眉妆、眼线、睫毛 | 眼睑、眉部及上睫毛边缘；睫毛是示意描绘 |
| 发色 | 按需加载独立头发分割模型，与面部图层叠加 |

`web/src/engine.ts` 将显示循环与推理分离；相机帧持续送入 WebGL，推理在 Worker 中单帧执行。面部定位使用 478 点 Face Landmarker，按时间自适应平滑；定位过期 350 ms 后撤妆。头发分割在另一个按需 Worker 中执行，过期 400 ms 后撤去发色。模型超时不会等待着旧画面，界面提示重试；离开、切后台、关闭镜头或换图时释放媒体与图像资源。

`web/src/renderer.ts` 使用 WebGL 1 像素合成，在线性 RGB 空间混色，并按原图亮度保留纹理。柔雾、缎光、水光、微光是可调视觉近似。模型 GPU 初始化失败会尝试 CPU；不承诺所有 iPhone 或浏览器都达到相同速度。

## 商品和隐私

41 款商品、538 个色号、12 个品类。`scripts/import-web-catalog.mjs` 从官网公开商品页提取名称、EAN、HEX、色号详情 URL；每品类最多取 4 个商品家族，去除家族重复。记录源 URL、抓取时间、HTML SHA-256 与色样性质。不虚构 SKU，也不声称覆盖全量在售商品。

照片、相机流、关键点和分割图仅存在于本机内存。模型和运行库随本站提供，不请求第三方推理 API。只有主动点击保存才生成本地图片；收藏与妆容只存商品 ID、色号和调节参数。官网详情跳转会打开品牌网站。静态托管服务可能记录普通访问日志，不接收应用图像。

模型固定版本和 SHA-256 见 `web/public/vendor/provenance.json`。官方模型与 MediaPipe 使用 Apache-2.0，许可随构建提供。依据：[面部 Web API](https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker/web_js)、[头发分割模型说明](https://ai.google.dev/edge/mediapipe/solutions/vision/image_segmenter)、[头发模型卡](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20-%20Hair%20Segmentation.pdf)。

## 已验证与未验证

开发用浏览器集成检查在 `web/tests/browser-check.ts`，不会被生产入口导入。测试图片来自用户提供的截图，裁剪仅在内存中进行，截图原有妆容不作为算法真值。检查报告在 `.artifacts/web-review`，不随站点发布。

- `model-render-check.json`：17 项通过。真实模型返回 478 点；唇色局部像素变化；粉底避开眼、鼻、口；张嘴留空；11 个面部蒙版、四种质感产生不同像素、叠妆、分屏/镜像/原图；真实模型跟随平移人像；无脸撤妆；非法保存参数清理。
- `hair-check.json`：7 项通过。真实头发模型分割；发区颜色变化而背景基本不变；定位过期撤色；平移后的区域跟随；无头发帧；WebGL 无错误。
- `camera-check.json`：6 项通过。生成的视频流驱动真实人脸模型；注入推理无响应后相机与合成画面仍继续变化；超时有提示；关闭时所有媒体轨道停止。生成流曾在内嵌浏览器中被节流，验证按源帧变化等待，不将其帧率当成摄像头性能。早期不充分采样的失败报告保留。
- 正式构建在启用内容安全策略的本地静态服务中成功加载面部、头发模型。手机尺寸 320×568 与 390×844 已检查：镜头固定、商品台独立滚动，无横向页面溢出。收藏和已存妆容刷新后保留；恢复色号、导出照片以及损坏图片的错误提示已检查。记录见 `ui-check.json`，效果截图见 `mobile-390.jpg`。
- 小程序回归：TypeScript 检查、208 项测试（19 个测试文件）及 WXML/WXSS 编译通过。未将这些本地结果表述为手机实测通过。
- 公网首轮测试暴露了慢下载触发 45 秒启动超时的问题。现已显示模型下载进度，将首次下载和启动的总预算调整为 180 秒；推理超时仍独立保持短时限，不延长旧蒙版的有效期。下载器的完整、截断、超长、HTTP 失败和非流式兼容 5 项检查通过；修改后真实人脸 17 项、头发 7 项及生成视频流 6 项回归通过，见 `model-loader-check.json` 和 `after-loader-regression.json`。

发布目录仅为 `dist/web`，不包含用户照片、测试报告、工作区源码或微信凭据。静态服务只允许 GET/HEAD，并拒绝工作区路径、目录穿越和提交请求。发布包与文件校验清单位于 `.artifacts/web-release`。经用户明确授权，2026-10-18 通过 Cloudflare 临时隧道发布至 [手机预览](https://accurately-abstracts-parts-investigators.trycloudflare.com)；访问说明见 `browser-preview-access.md`。公网访问范围 8 项检查通过，公开页面真实模型已成功定位照片并显示 300 Le Rouge Paris 唇色；见 `public-server-check.json`、`public-browser-check.json` 和 `public-mobile-390.jpg`。

这些是桌面浏览器行为与像素检查，未覆盖真实 iPhone 摄像头、长时间运行发热、逆光和强侧脸的连续画质。手机浏览器版的真机验收尚待用户扫码：确认唇色换色、脸部左右移动、张嘴眨眼、粉底排除五官、叠加发色、切前后相机、对比/保存、后台再回来，以及持续两分钟运行。

## 与商业服务的差距

这不是 ModiFace 私有 SDK 的复刻或同等画质认证。未获得品牌实物色彩、成膜质感、遮盖力的标定；公开 HEX 不足以预测真实上妆。现有皮肤相近色匹配基于当前光照的像素近似，不能称为训练过的肤色推荐模型。

仅支持单人试妆。手遮脸、头发遮脸、强侧脸、薄发边缘、运动模糊和极暗光可能造成蒙版不贴合。面部图层没有完整的手部遮挡分割或三维自遮挡材质；睫毛不预测增长/卷翘；染发不预测漂染、白发覆盖和化学处理结果。浏览器版未移植小程序的 A/B 局部色差圈选，原有流程仍在小程序；两者都不是皮肤疾病诊断。
