# 自动人脸试妆 v0.4

本文保留 v0.4 的历史实现与验证。后续用户反馈 iPhone 上妆效未显示、镜头卡住；现行修复与新的验证结果见 [实时跟踪 v0.5](realtime-tracking-v0.5.md)。下文的帧绑定方式、250 毫秒定位阈值和预览码不再代表当前版本。

更新：2026-10-16。目标是把参考产品的“镜头中直接换妆、分区叠加、即时对照”融入 EVEN TONE 的梅子色主题。当前实现了自动人脸定位接入和三层合成；手机实际效果尚未验收，不能称为达到商业试妆产品的自然度。

## 体验与实现

实时页默认“人脸试妆”，使用前置相机，不要求 A/B 校准。底妆、唇色、腮红分别开关；切品类保留其他层。唇色有五种概念色与缎光/柔雾，腮红有三种概念色；底妆保留三种模拟配方、相对色调和精细微调。分屏与按住原图用于对照。首页仍提供当前手机拍照与相册；“局部遮瑕”保留手动确认选区，适用于脸外的局部试妆。

人脸模式的镜面高度不超过可用窗口的 42%，完整保留相机帧宽高比，不裁切或拉伸。滚动色盘和微调区域时镜面吸顶；分屏触点按实际显示宽度计算。局部遮瑕仍按页面宽度显示，方便圈选。

`face-detector.ts` 使用微信 VisionKit 的手动人脸模式：`track.face.mode = 2`，`detectFace` 接收最长边 256 的 RGBA 帧，`modelMode = 1`、`sourceType = 0`，通过 `updateAnchors` 接收 106 个二维关键点。一次只允许一项推理，结果与同一张最长边 640 的相机帧绑定；不能把旧关键点画到更新的相机帧上。1200 毫秒未返回即销毁会话；8 秒未完成启动则提示。模型内部的运行行为由微信提供，本项目不下载或训练病灶模型。

`face-makeup.ts` 根据轮廓、眼眉、外唇和内唇生成独立蒙版。底妆避开眼眉和嘴，唇色排除口腔，腮红沿双颊渐隐。肤色和唇部亮度取自当前画面；蒙版随二维关键点的转动与尺度变化重建。`live-renderer.ts` 在 linear RGB 中合成并保留部分亮度纹理。每层独立权重；控件只更新参数并重绘，不等待下一张相机帧。

蒙版边界由 `polygon-mask.ts` 按扫描行求交并填充像素中心，避免对每个像素重复遍历所有轮廓。眼眉、嘴部挖空与透明像素处理仍在羽化之前执行。像素恰好落在边界时，沿用原实现的左/上包含、右/下排除规则。

仅接受一个满足几何/置信度要求的人脸。未检出、多人、极端侧脸或定位超过 250 毫秒时撤妆；新鲜单脸结果可恢复。250 毫秒是代码阈值，不是延迟实测。退出、切后台、切换模式/镜头、五分钟无操作会停止取帧，销毁定位会话，清理应用持有的图像与 GPU 纹理。没有新增上传、保存或人脸身份识别。

## 验证与证据

- `npm run verify`：TypeScript 通过，18 个测试文件、193 项测试通过。覆盖异步帧对应、超时/迟到回调、销毁、多人撤妆、分区边界、旋转/缩放几何、三层独立控制，以及竖屏镜面尺寸与分屏触点映射；新增像素中心边界、凹多边形/交叉/非方形画幅与独立逐像素参考对照，以及透明皮肤/唇部排除。
- 蒙版优化对照：60 组合成输入（6 种画幅、5 个旋转角度、含/不含透明切口）与保留的旧编译实现逐字节一致，肤色元数据一致、输入未修改。桌面 Edge 155 对 256×256 合成帧预热后交替测量各 150 次，生成蒙版中位耗时从 19.1 降至 11.2 毫秒（约减少 41%），P95 从 20.0 降至 12.4 毫秒。报告、原始样本、编译代码散列和复现脚本位于 `.artifacts/face-performance/`；不包含相机、VisionKit、GPU 或显示时间，不是手机帧率或端到端测量。
- `npm run test:live-renderer`：本机 Edge 实际 WebGL 检查通过。合成蒙版的底妆、唇色、腮红分别改变 3652、200、430 像素，三层合计 3852；各检查蒙版外改变 0，禁用全部层/原图/零强度/撤妆恢复原始像素。局部模式的 9 组 CPU 对照最大通道误差为 1。报告：`.artifacts/live-renderer/report.json`。
- `npm run check:wechat`：官方 WXML/WXSS 编译通过。它只证明模板/样式可编译。
- `npm run review:ui`：75 种浏览器辅助布局状态通过，包括人脸底妆、唇色、腮红以及定位不可用时的局部遮瑕入口；没有横向溢出、小于 44×44 的按钮或文字横向挤出。另检查滚到色盘时镜面与色盘同时完整可见、画面比例保持，含 320×568 小屏。它不运行微信 API。
- `npm run test:native-face`：20:27–20:28（UTC+8）8 项功能检查通过：自动进入人脸模式、原生点击选择唇色与质感、处理方法叠加三层与分屏、未检出/多人/迟到定位撤妆、退出销毁。测试使用合成帧和预设 106 点，不构成人脸模型精度或真人妆效证据。5 项清理步骤通过，最后的恢复断言因自动化导航超时失败，因此原报告 `passed: false` 原样保留；随后独立重试确认真实相机/定位 API 存在、测试状态已清除、已回到首页。报告：`.artifacts/native-face/report.json`。
- `npm run test:native-face -- --layout`：蒙版优化后于 20:59:13–21:00:14（UTC+8）再次通过 9 项功能检查与 6 项清理，报告 `.artifacts/native-face/layout/report.json`。实际页面滚动约 120.7 px 后，镜面顶部为 0，色盘上下边界约 536.4/604.4 px，均在 753 px 窗口内；合成方形帧仍显示为正方形。20:46 的旧报告与截图保存在 `before-mask-optimization/`。首次布局检查因工具刚打开、自动化未就绪而失败，报告保存在 `layout/report-first-attempt.json`；脚本现在在打开窗口后用最多三次只读探测等待就绪，不重试测试动作或隐藏失败。
- `npm run test:native -- --photo-camera`：20:29:34–20:31:47（UTC+8）旧照片与局部实时流程回归，17 项流程和 6 项清理检查全部通过。它也再次确认重开后的原生接口恢复正常。报告：`.artifacts/native-photo-camera/report.json`。
- 桌面环境实际 `wx.createVKSession` 存在，但手动人脸会话启动返回 `2000004`。因此必须通过手机预览验证原生推理。调试用合成会话不打包进小程序，回归后恢复真实 API 并重新打开项目。

开发者工具的通用 `mockWxMethod` 丢失了同步人脸会话对象的方法，原生回归因此改为在调试运行时替换会话。开发者工具的异步定时回调也曾延迟超过 1 秒，使过期保护撤妆；原生正常路径采用同步合成定位，异步安全由专门测试和原生延迟用例覆盖。不能由合成回归推断真实定位速度。
