# 实时试妆镜 v0.3 工作记录

> 历史记录：下文描述 v0.3 的黑白金界面与局部跟踪。当前梅子主题见 [视觉方向](visual-direction.md)，新增自动人脸叠妆及其验证边界见 [v0.4](face-mirror-v0.4.md)。

## 体验目标与设计

参考 [L’Oréal Paris Virtual Try-On](https://www.lorealparisusa.com/virtual-try-on-makeup) 的大幅镜面、即时换妆、原图分屏。保留 EVEN TONE 的局部匀色目标，不使用参考网站的商标素材或商品色号。

设计色：纸白 #ffffff、墨黑 #151515、浅灰 #f7f7f6、暖金 #d8bb87、金棕 #70552d、圈选莓红 #962b43。字标使用 DIN Alternate / Arial；中文使用苹方 / 微软雅黑。唯一主视觉是用户自己的试妆画面，工具围绕画面排列。

布局：品牌栏 → 翻转工具栏 → 单一大幅试妆镜 → 分屏、按住原图 → 妆效与肤色偏移 → 遮盖强度。细调收起以减少镜头下方的操作负担。原方案的独立相机小窗已移除，原生相机位于合成画布下方。原生画布会遮住普通叠加元素，因此操作按钮位于画布外，A/B 圈选标记直接绘入预览；关闭后移出未使用画布，恢复空状态说明。

## 实现

- 原生 camera 使用 medium 帧，WebGL 直接上传原始 RGBA 纹理。选区分析独立缩小至最长边 256；显示不再被分析分辨率限制。
- 显示入口最多约 30 次/秒，分析最多约 15 次/秒；这是代码调度上限，不能当作手机实测帧率。
- 合成在 linear RGB 中进行，保留亮度纹理、边缘羽化，提供三种创意妆效。与照片引擎共享参数含义。
- 修改强度、冷暖、明度、妆效或分屏会立即重绘已有画面，不等待下一相机帧。WebGL 不可用时保留 Canvas 2D 路径。
- A/B 标记仅影响显示，不修改取样来源；结束校准后撤去。GPU 与 CPU 路径保持一致。
- 短暂跟踪丢失时立即撤去妆效。在原区域附近连续两次通过颜色、面积、位移和周边肤色检查后恢复；累计 20 次丢失后需要重新圈选。
- 授权超时、页面退出、切镜头、帧中断时，清除 CPU 图像、选区与 GPU 纹理，保留原来的授权代次保护。

## 完整目标的剩余验收项

尚不能将此版本称为达到参考产品效果：需要手机实际摄像头上的显示方向、画布覆盖、运动贴合、低照度及帧率验证。自动面部定位、无需 A/B 取样的自动圈选、姿态旋转与尺度变化跟踪仍未实现；当前为用户确认的色差区域跟踪。五个色调按钮为相对周边肤色的偏移示意，不是品牌商品色号。

手机拍照入口已经使用 `chooseMedia` 的 camera 来源，需在手机微信扫描预览码进入。桌面模拟器使用电脑相机，不会远程启动手机相机。

## 本地验证证据

- TypeScript 与 14 个测试文件中的 171 项测试通过。新增检查覆盖即时重绘、按住原图、短暂遮挡恢复、恢复候选跳变和跟踪过期。
- `npm run test:live-renderer` 在本机 Edge 的实际 WebGL 上对照照片 CPU 引擎。三种妆效 × 三种显示模式共 9 组，最大通道误差为 1，选区外没有像素改变；零强度、无选区与清理检查通过。
- 240×200 原始图与 96×80 选区的不同分辨率组合检查通过，原图模式逐像素一致。这验证坐标与合成实现，不证明真人肤色或商品效果。
- 圈选标记的 GPU / CPU 结果逐像素一致；原始取样像素保持不变，撤去标记后恢复原图。
- 官方 WXML / WXSS 编译通过。2026-10-16 19:20（UTC+8）的 54 种浏览器辅助排版状态检查通过。
- 19:15–19:18（UTC+8）的原生联合回归通过 13 项流程检查、6 项清理检查。采集接口使用合成夹具；连续帧下换妆/对比通过真实页面处理方法验证，不是实际触摸验证。详情与自动化限制见 [原生调试记录](native-validation-2026-10-16.md)，手机实测仍按 [真机验收模板](device-validation-template.md) 执行。
