## 已修复的问题

- **原生白屏**：微信加载器没有解析 `./session` 等目录简写，报 `module 'session.js' is not defined`。改为显式 `./session/index` 等文件路径；增加本地相对导入检查，防止 TypeScript 能解析而原生运行失败。
- **无效配置**：移除工具不接受的 `app.json permission.scope.camera` 配置键。保留用户主动开启后的相机授权流程。
- **取样标记拥挤**：移除圆框旁重复的浮动说明，保留 A/B 字母、完整操作标签与辅助朗读名称。已检查原生截图。
- **相机授权无反馈**：增加加载状态、防重复点击和 10 秒无回调超时。超时后恢复重试，迟到授权不能打开已经关闭的相机；用户阅读隐私说明期间不计入这一超时。
- **自动化接口恢复污染**：本机工具中，对未配对的接口重复调用 `restore` 会使 `wx.authorize` / `wx.createCameraContext` 变为 `undefined`，普通编译不能恢复。测试改为重开项目后再执行，仅恢复本次替换的接口；退出时重开项目，并断言原生接口存在且合成状态已清除。
- **实时画布遮挡**：将翻转、分屏与原图按钮放到画布外，A/B 圆环直接绘入预览。未使用的画布移出显示区，关闭后不再用黑色画布遮住提示。已目视核对最新校准、分屏及关闭状态截图。

## 重现

先在开发者工具登录、开启服务端口，并允许本机 `local-debug` 客户端。MCP Token 仅放在当前终端环境的 `WECHAT_MCP_TOKEN` 中，勿写入源码、日志或提交配置。端口不同可设置 `WECHAT_MCP_PORT`，默认 `49173`；客户端只连接 `127.0.0.1`。

```powershell
npm run verify
npm run check:wechat
npm run test:live-renderer
npm run review:ui
npm run test:native
# 自动人脸交互，使用明确标记的合成帧和关键点：
npm run test:native-face
# 从首页拍照按钮检查照片流程及实时回归：
node scripts/native-smoke.mjs --photo-camera
# 只检查实时管线：
node scripts/native-smoke.mjs --live-only
# 单次观察真实授权，不替换权限或相机：
node scripts/check-camera-permission.mjs
```

原生回归会重新编译、清除当前开发会话并替换媒体接口，请使用没有待保留照片的开发模拟器。原生自动化桥接对某些异步调用或 Canvas 对象的传输有限制；脚本将等待放在宿主侧，画布节点留在应用运行环境，只传递可序列化结果。

当前本地检查为 TypeScript 通过、19 个测试文件共 208 项通过、官方 5 个 WXML / 6 个 WXSS 编译通过、77 种浏览器辅助排版状态通过。独立 Edge WebGL 检查中，9 组局部模式结果与 CPU 参考最大通道误差为 1；人脸分层合成以及蒙版平移、缩放、旋转后，蒙版外改变均为 0 像素；当前视频继续更新与撤妆检查通过。报告在 `.artifacts/live-renderer/report.json`。辅助排版报告仍标记 `nativeWeChatValidated: false`，因为该报告自身不执行微信 API；不要与独立原生验证混淆。
