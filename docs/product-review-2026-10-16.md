# 黑客松产品自评与改进记录

> 历史阶段记录：以下内容描述 v0.1 三页取色原型，133 项测试为当时结果。用户随后明确要求照片与摄像头试妆，本轮已扩展至五页；当前能力、复评和验收边界以 [虚拟试妆 v0.2](virtual-tryon-v0.2.md) 为准。

日期：2026-10-16。依据：开发指导文档、当前源码和本地自动测试。这是产品经理的判断，尚无用户访谈、实际试色效果或赛事评审数据支持。

## 产品判断

定位应该是“帮助主动有遮瑕需求的用户确认目标肤色，缩小真实色号的试色范围”。A 为待遮盖处，B 为用户希望接近的周边肤色，这个操作关系直观，也保留了用户纠错权。本地处理、不登录和不留历史，使首次体验负担较小。

当前实现仍是本地取色交互原型。正式商品目录为空，普通照片也没有经过验证的颜色可比依据。因此，用户完成操作后只能核对照片中的颜色，尚不能完成“减少买错色号”的核心任务。以黑客松产品经理视角看，这比增加页面或动画更影响项目竞争力。

| 维度 | 判断 | 当前依据与影响 |
| --- | --- | --- |
| 用户价值 | 目标清楚，收益未验证 | 原文档明确减少试色选择成本；当前不能输出真实商品候选，未验证是否改善决策 |
| 差异化 | 解释与隐私有特点，技术优势未证明 | 用户自己确认 A/B、照片本地处理；不能把手动取样称为 AI，也没有与其他选色方式的效果对比 |
| 易用性 | 本轮已降低纠错成本 | 自动引导 A→B、默认收起微调、一次撤销、结果图片标记位置；仍需观察真实用户能否理解和完成 |
| 可信度 | 边界清楚，需要管理预期 | 不补虚构 SKU、不把普通照片做可靠排序；本轮把商品未接入提前告知 |
| 演示完整度 | 本地流程可验证，现场运行待验收 | 页面处理逻辑与算法测试通过；开发者工具编译、真机权限/性能/读屏尚未验证 |
| 商业闭环 | 未完成 | 缺少经核验的商品、色样依据和官方路由；不能宣称已带来购买转化 |

结论：可以展示透明、可纠错的本地取色过程；还不足以宣称是经过验证的智能选色产品，不能据此预测获奖或商业效果。

## 本轮已实施

| 发现的问题 | 已修改行为 | 为什么优先做 |
| --- | --- | --- |
| 入口承诺色号建议，最后却无商品 | 首页说明“本次可体验：照片取色”，按钮改为“拍照取色”，流程末步统一为“查看结果” | 用户在提交照片前知道能得到什么 |
| 首次取样面对过多按钮 | 第一次放置 A 后自动引导 B；方向和范围按钮收进“微调范围与位置” | 简化默认操作，同时保留非拖动方式 |
| 放错位置或误调范围不易恢复 | 新增一次“撤销上次”，恢复位置/范围 | 纠错仍更新修订号，旧分析必须重算 |
| 手动选 A 可能被缺少 B 的规则覆盖 | 明确选择的区域优先，提示随选择更新 | 操作与反馈一致 |
| 结果看不到 A/B 原先取在哪里 | 展开照片可看到带字母的圆形标记，按固定分析图比例定位 | 核对颜色来源，横竖图半径保持一致 |
| “暂无候选”容易引导无意义重拍 | 区分目录为空、没有适用商品、未校准、缺少可比依据；优先说明数据缺口 | 系统资料不足不能归咎于用户拍照 |
| 曝光提示在结果页丢失 | 保留检测到的 A/B 过曝或欠曝提示 | 质量提示贯穿流程 |
| 缺少明确结束动作 | 增加“完成并清除本次图片”；首页跳转失败时显示已结束并允许重试 | 用户有明确退出与清理入口 |
| 迟到的页面刷新可能恢复旧内容 | 清除取样页图像引用，阻止旧快照重新渲染；撤销不能恢复过期/替换图片 | 结束行为与隐私说明一致 |
| 新测试暴露纯白取样分析失败 | 修复 sRGB 矩阵舍入导致白色 L* 略超 100 的边界，换算版本更新为 `srgb-d65-cielab-v2` | 过曝取样应保留警告，不应因数值漂移失败；非法输入仍被拒绝 |

交互改进应用 frontend-design 与 interaction-design 的原则：以 A/B 为统一标识，减少默认可见控件，并为纠错、警告和结束动作提供真实状态反馈。后续视觉适配将界面统一为黑白与金色细节，见 [视觉方向](visual-direction.md) 与 [界面验证记录](ui-validation-2026-10-16.md)。没有增加业务页面、账号、上传、历史或模拟商品模式。原始开发指导文档保留；按钮文案调整属于本次产品改进，不改变真实商品推荐的最终目标。

## 验证记录

`npm run verify`：TypeScript 检查通过，11 个测试文件、133 项测试通过。

新增测试运行真实页面处理函数、会话存储和分析逻辑，仅模拟微信视图桥接与导航。合成像素只在测试目录使用，不作为真实肤色、产品数据或演示效果证据。

已覆盖首次 A→B 引导、明确选择 A、撤销初次放置/范围调整、按钮方式完成取样、重叠阻止分析、撤销使旧结果失效、换图/过期拒绝旧撤销、无候选原因、结果曝光提示、横竖图标记几何、返回失败与延迟页面刷新下的清理。

自动测试不等于微信渲染、开发者工具编译、真机体验或真实选色有效性。照片清理指应用持有的会话数据与引用，微信或系统临时缓存不承诺立即物理擦除。

## 下一阶段优先级

| 优先级 | 工作 | 可验收的完成条件 |
| --- | --- | --- |
| P0 | 核对赛事要求 | 确认用户、品牌/技术范围、是否要求 AI、现场演示规则；当前没有任务书，不能猜测评分权重 |
| P0 | 打通一个真实产品系列 | SKU、来源、素材权限、可用状态齐全；照片与色样有验证过的可比协议，或存在可追溯的官方参考映射。只补 LAB 表格不足以启用排序 |
| P0 | 完成微信现场主流程 | 真实 AppID，在指定 iOS/Android 设备完成取图、方向、取样、结果、纠错、过期与清理验收并留存证据 |
| P1 | 验证用户收益 | 经同意观察首次完成、误选区域、撤销/重试、是否理解照片色与实物色的区别；商品接通后再比较选色耗时与实际试色选择质量 |
| P1 | 打通官方商品出口 | 产品、色号、路由、落地页面一致；确认会自动选中 SKU 后才使用相应承诺 |
| P2 | 评估自动建议区域 | 合法模型和设备性能证据齐全，保留手动确认与纠错。若赛事强制 AI，则按要求调整优先级 |

上述用户研究和商品实验尚未执行，没有完成率、准确率、转化率或耗时收益可报告。观察记录应经同意且尽量不收集照片，不为测量指标擅自引入图片上传或用户追踪。

当前最值得投入的下一步是一个可核验的真实商品闭环，而不是扩张功能数量。
