# 实时镜头与跟脸修复 v0.5

更新：2026-10-16 22:57（UTC+8）。用户已在 iPhone 微信中看到相机画面，但先后反馈妆效未显示、定位提示切换，最近一版画面卡住。本次完成代码修复和本地验证，已生成新的普通预览；新版本的手机流畅度、颜色可见性与贴合度仍待验收。

## 修复内容

代码中存在明确的冻结路径：人脸蒙版有效时停止上传新相机帧，只在原生定位回调到达时显示该次推理对应的旧图。慢定位因此拖住视频刷新。现在每个接受的相机帧都上传并绘制，定位回调只更新蒙版，不再替换视频。即使未检出、定位迟到或跟踪失败，新的相机帧仍能显示。

定位与运动跟踪分开执行。微信 VisionKit 在最长边 256 的私有 RGBA 副本上检测 106 点；两次检测之间，在最长边 160 的灰度图上追踪眼眉、鼻部与唇边附近的纹理点。局部块匹配使用亮度偏移补偿、前后向一致性和多点一致性筛选，估计平移、缩放与平面旋转。GPU 将这项变换应用于蒙版，视频保持最新。慢于相机的检测结果通过短时灰度历史对齐到当前帧；没有足够纹理证据就撤去蒙版，不把旧蒙版硬贴到新画面。

灰度历史最多保留 32 帧、900 毫秒；900 毫秒内必须有新的人脸检测结果，连续相机帧间隔超过 250 毫秒即撤妆。这两个值是失效保护参数，不是手机实测延迟。原生推理仍只有一项在途请求，首次返回允许模型预热；不会把等待中的推理累积成队列。退出、切后台、切换镜头/模式时清零私有灰度缓冲并停止会话，没有新增照片上传或主动保存。

底妆蒙版现在避开眼周、眉毛、嘴唇和鼻部，并向内羽化边缘。唇色仍由独立开关控制，默认关闭。未参与蒙版的可选瞳孔点不再导致整张脸被拒绝，实际使用的点仍进行坐标和置信度检查；尚无证据证明可选瞳孔点是此前 iPhone 定位失败的原因。

延续 [美妆视觉方向](visual-direction.md)：镜面保持可见，底妆/唇色/腮红分组和色盘不重置；定位期间保留对照栏位置并禁用无效操作，减少界面跳动。定位丢失时释放“按住看原图”的状态，避免恢复后仍停留在原图。

## 手机确认与剩余边界

新预览码：`.artifacts/native-face/phone-preview-live-motion-v05.png`。退出旧预览后重新扫码，进入“人脸试妆”，选择“底妆 → 浅一度”，缓慢移动/轻微转动头部；观察视频连续、皮肤颜色随脸移动、眼鼻唇不被底妆覆盖，再按住看原图对照。只有手机实际通过后才能登记这些验收项。当前精确 iPhone 型号与 iOS/微信版本尚未取得。

本次仍是二维跟踪和颜色合成，不是三维可变形面网格或皮肤语义分割。大幅侧转、开口表情、手/头发/眼镜遮挡可能导致失配或撤妆；历史对齐不能保证这些场景天衣无缝。现有局部圈选也不识别白癜风，未新增病灶模型或真实商品色号。

参考接口：[微信官方手动人脸检测样例](https://github.com/wechat-miniprogram/miniprogram-demo/tree/master/miniprogram/packageAPI/pages/ar/photo-face-detect)。视觉参考与转化来源见现有视觉方向文档；参考展示图不构成本项目自然度的实测证据。
