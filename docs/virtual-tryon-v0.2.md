# 照片与摄像头虚拟试妆 v0.2

日期：2026-10-16。范围依据是用户后续明确提出“圈出部位、模拟不同化妆品”，并确认照片即时试妆和摄像头实时试妆“两个都要”。原 v0.1 文档保留，其三页及不做试妆的约束由本次明确需求扩展；商品真实性、来源、隐私和不冒充医学诊断的边界继续保持。

## 已实现

| 用户目标 | 当前实现 | 限制 |
| --- | --- | --- |
| 圈出待遮盖位置 | A/B 取样、LAB 颜色差异、连通区域生长、金色轮廓 | 要求用户提供 A/B；不是全图皮肤/病灶识别，不能判断白癜风 |
| 修正圈选 | 点击补选其他相似斑块、连续涂抹、擦除、六步撤销、容差重算 | 复杂背景、头发、高光、低色差需要人工修正 |
| 看不同妆效 | 轻薄底妆、局部遮瑕、柔焦底妆三种模板；强度、冷暖、明度、边缘柔化 | 模板参数是工程设定，没有真实商品的遮盖力/光谱标定 |
| 对比前后 | 原图、妆后、可调整分界线的左右对照 | 非色彩校准照片；屏幕效果不能保证实物相同 |
| 摄像头随动 | 逐帧取图、定格 A/B 校准、轮廓确认、局部重新分割与跟踪 | 实验模式，仅适合稳定光线下的小幅缓慢移动；无三维人脸或人体部位跟踪 |

| 安全退出 | 切后台停止相机、忽略旧帧与旧镜头事件、权限请求 10 秒超时恢复、无帧超时清画面、五分钟无操作清理 | 微信与系统自身的临时缓存不承诺物理擦除 |

## 处理流程与文件

`miniprogram/tryon/engine.ts` 是照片和实时模式共用的纯像素引擎。`tracker.ts` 管理实时选区的接受/失效状态；`canvas.ts` 只负责像素绘制和坐标转换。页面数据桥只传控件状态，不传整帧像素。

1. 读取已经校正方向的照片像素，或微信相机回调提供的 RGBA 帧，生成有尺寸上限的私有副本。照片长边不超过 640，相机处理长边不超过 320。
2. 用 A 和 B 的颜色作参考。像素须与 A 足够相近且更接近 A，才可从种子扩展为四连通区域；B 的取样圆受到保护。相似色背景仍可能误选，因此先显示轮廓，由用户确认。A/B 太相近时不生成可靠选区，而提供手动修正。
3. 照片模式允许补选、涂抹、擦除。每次手势保留一个可撤销状态；调整容差重新圈选，也可撤销。
4. 渲染在线性 RGB 中混合参考肤色与原像素，并按 A 的平均亮度保留局部明暗；不同模板采用不同遮盖与明暗保留系数。只在掩膜内部柔化边缘，掩膜外像素保持原值。原图模式返回原始预览副本。
5. 实时模式先冻结一帧，用两处小圆的 RGB 中位数校准。确认轮廓后，在上次区域附近寻找相似颜色种子，再重新分割；检查面积、质心位移、边界和参考色变化。失败后保持原图，直至用户重新校准。

实时处理以至少 160 毫秒的接收间隔限流，不宣称 30/60 FPS。原生相机小取景框和试妆画布分开，试妆画布绘制完整处理帧，避免直接将掩膜贴到可能裁切或镜像的原生预览上。实际前后镜头方向、旋转、帧尺寸以及端到端延迟仍须真机核验。

## 产品经理复评

之前的核心问题是：用户选完图片只能得到取色结果，难以看到遮盖方案。现在，照片流程有可见妆效、对照和纠错，摄像头入口也实现了可校准的逐帧路径，演示叙事更完整。界面继续应用 frontend-design 的统一视觉层级和 interaction-design 的状态反馈：先确认轮廓再试妆，丢失跟踪显示原图，结束时清除应用数据。

当前仍不能宣称“已验证的白癜风识别＋真实产品 AR 试妆”。决定下一步质量的三项缺口是：真机拍摄和性能证据；经同意、覆盖多肤色与光照的选区验证；可追溯的真实商品色样及遮盖参数。没有进行用户研究、患者测试或产品实测，不给出准确率、用户完成率、转化率或获奖预测。

实时跟踪目前没有多区域独立跟踪、深度遮挡、三维转头补偿、光照估计或神经网络病灶分割。手臂/手背等相对平坦区域应先验证；不能把合成帧中的平移测试当成真实人脸 AR 能力。

## 参考与实际采用范围

- [OpenCV 的 floodFill 文档](https://docs.opencv.org/4.13.0/d7/d1b/group__imgproc__misc.html)：参考种子连通区域思想。本项目自行实现 LAB 条件生长，不依赖 OpenCV。
- [OpenCV 官方 GrabCut 交互示例](https://github.com/opencv/opencv/blob/5.x/samples/python/grabcut.py)：参考“先给建议、用户修正前景”的流程。没有集成 GrabCut，也不把当前算法称为 GrabCut。
- [MediaPipe Face Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker)：用于评估未来人脸地标/变换矩阵方案。当前未集成它，它也不能替代白斑选区识别。
- [微信官方 Canvas API 类型](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.canvas.d.ts) 与本机官方 API 类型：核对 Canvas 和相机帧接口；运行时使用微信原生 `CameraContext.onCameraFrame` 与 2D Canvas。
